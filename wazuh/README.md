# Wazuh Detection Rules

This directory contains custom Wazuh detection and correlation rules developed during the cybersecurity monitoring project.

The rules extend Suricata event analysis with network reconnaissance detection, threat intelligence correlation, Active Response monitoring and AbuseIPDB enrichment.

## Rule Overview

| Rule | Level | Purpose |
|---|---:|---|
| `100200` | 6 | Detect Suricata `ET SCAN` events |
| `100201` | 10 | Correlate repeated scans from the same source |
| `100202` | 8 | Detect scans against critical services |
| `100203` | 12 | Detect malware-related network activity |
| `100204` | 12 | Detect possible Command & Control activity |
| `100205` | 11 | Detect possible exploitation attempts |
| `100206` | 10 | Detect possible phishing activity |
| `100207` | 10 | Detect suspicious Discord webhook/exfiltration activity |
| `100209` | 12 | Correlate repeated scans against critical services |
| `100210` | 12 | Detect MISP IOC matches generated by Suricata |
| `100220` | 10 | Confirm MISP IOC Active Response blocking |
| `100230` | 5 | Record AbuseIPDB reputation enrichment |
| `100231` | 10 | Highlight high-confidence malicious IP reputation |

## Network Scan Correlation

Rule `100200` identifies Suricata events containing `ET SCAN`.

Rule `100201` then correlates repeated scan events originating from the same source IP.

The correlation threshold used in the final project was:

- 3 matching events
- Within 300 seconds
- From the same source IP

This allows individual Suricata events to be transformed into higher-level reconnaissance alerts.

## Critical Service Monitoring

Rule `100202` identifies suspicious activity targeting services such as:

- SSH
- RDP
- MSSQL
- MySQL
- PostgreSQL

Rule `100209` correlates repeated activity against these services from the same source.

## Threat Detection

Additional rules were created to classify Suricata alerts associated with:

- Malware
- Command & Control traffic
- Exploitation attempts
- Phishing
- Suspicious Discord webhook or exfiltration activity

Several rules were mapped to relevant MITRE ATT&CK techniques.

## MISP IOC Detection

Rule `100210` processes Suricata alerts generated when network traffic matches an IP reputation IOC imported from MISP.

Detection flow:

MISP → IOC Dataset → Suricata → Wazuh → Rule 100210

This rule was also used as the trigger for the local Active Response proof of concept.

## Active Response

Rule `100220` confirms the execution of the MISP IOC blocking mechanism.

When an IOC was detected, Wazuh could execute the `misp_ioc_block.sh` script on the Suricata IDS agent.

The response created a local `iptables` DROP rule on the Suricata virtual machine.

This was implemented as a proof of concept and should not be interpreted as perimeter-wide blocking.

## AbuseIPDB Enrichment

Two rules were used for AbuseIPDB reputation enrichment:

- `100230` — records successful reputation enrichment
- `100231` — highlights IP addresses with an abuse confidence score of 70 or higher

The enrichment included information such as reputation score, reports, country, ISP, domain and Tor usage.

## Noise Reduction

A level `0` suppression rule was also used to reduce unnecessary SSDP-related alert noise.
